Insightly SE MCP — Cloudflare edition

Same tool, different spine. The whole MCP server now runs as a stateless Cloudflare Worker; what you install locally is a ~100-line bridge that forwards requests and keeps your API keys on your own machine. That move buys capabilities the laptop version cannot have — server-side aggregation, field projection, snapshot queries, CSV deliverables — and makes every future release a deploy instead of a re-download.

Why move the MCP layer to a Worker

Insightly's API has no field selection, no batch reads, no filtering, no sorting and no aggregation. On a laptop those gaps land in your chat window. At the edge, they get absorbed before anything reaches the conversation.

Field projection Ask for three columns and get three columns. The Worker still pulls the full 100 KB record — the API offers nothing smaller — but it dies at the edge. Reading one ARR field off 47 organisations went from ~3.5 MB and 35+ tool calls (abandoned mid-way) to 15 KB in two calls.
Real aggregation aggregate does group-by / sum / count / avg server-side. "Total opportunity value by stage" returns a small table instead of an export plus arithmetic in chat. Large objects stream into a background job that keeps only running totals.
Exports become queryable Export an object once, then task_query it repeatedly — sort by any field, filter, group, project. The snapshot lives at the edge, so a 167k-row question costs one scan, not one per question.
Deliverables escape the chat export_csv turns a finished export into a real CSV file and hands back a download link, sidestepping the 1 MB ceiling on tool results entirely.
Whole-environment search & joins search_everywhere sweeps every object including custom ones in parallel. join_related merges linked-record fields into one table — the join the API cannot do.
Releases without reinstalls Logic lives in one deployment, so improvements arrive server-side. The bridge watches for changes and refreshes the tool list mid-session — no re-download, no ⌘Q ritual per release.

Measured, not asserted

Same account, same API key, same questions — laptop server versus Worker, against a 548,000-contact org.

Insightly enforces about 10 requests per second per API key, which no architecture beats. The gain comes from filling that ceiling with six parallel lanes instead of one sequential queue — so it shows up on big environments and disappears on tiny ones.

Where your data goes

Claude desktopRuns the small local bridge as an extension.
→
Cloudflare WorkerExecutes the tool, calls Insightly, trims the result. Holds no state between requests.
→
Insightly APIReached from the edge with the key your request carried.
  • Your API keys never leave your machine. They live in the same local keystore the classic extension uses, and travel as a per-request header over TLS. The Worker stores nothing — the one exception is a running background export, which holds the key only until the job finishes.
  • Environment management runs locally. Adding, switching, renaming and removing environments all execute in the bridge on your laptop, never on the server.
  • CSV links are unguessable but public. Anyone with the link can download that file for about 7 days, after which it deletes itself. Fine for demo data; think before generating one from anything real.
  • Records pass through Cloudflare in transit while a tool runs. Nothing is persisted there apart from a background export's own snapshot, which expires after an hour.

Install — macOS

You'll need your Insightly API key: in any demo environment, click your profile picture (top right) → User Settings → API and copy the key.

  1. 1

    Install uv (one Terminal command)

    Open Terminal (⌘Space, type “Terminal”, Return), paste this whole line, press Return:

    curl -LsSf https://astral.sh/uv/install.sh | sh && echo "YOUR UV PATH: $HOME/.local/bin/uv"

    Copy the path it prints after YOUR UV PATH: — you'll paste it in step 3.

    Already have Homebrew's uv? brew install uv is fine too; the field in step 3 is then already correct at /opt/homebrew/bin/uv.

  2. 2

    Download and double-click the bridge

    Use the button above; the file lands in Downloads. Double-click it and Claude opens an install dialog.

    Nothing happens? In Claude: Settings → Extensions → Advanced settings → Install extension… and pick the file.

  3. 3

    Fill in the dialog (2 required fields)

    Insightly API key — paste the key. It is stored by Claude and written to your local keystore; it never appears in chat.

    Name this environment — a short label like demo1. This is how you'll switch later (“switch to demo1”), and you can add more environments from the dashboard afterwards.

    Path to uv — paste the path from step 1.

    Leave pod as na1 unless your Insightly URL says otherwise, and leave the server URL alone.

  4. 4

    Restart Claude fully

    ⌘Q (closing the window is not enough), then reopen.

Install — Windows

Same four steps; only the uv install differs, and you can ignore the uv path field entirely because Windows finds it automatically.

  1. 1

    Install uv (one PowerShell command)

    Press Win, type PowerShell, open it, then paste this line and press Enter:

    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

    It installs to %USERPROFILE%\.local\bin\uv.exe and adds that folder to your PATH. Close PowerShell when it finishes — the PATH change only reaches programs started afterwards, which is why the next step matters.

    Confirm it worked: open a new PowerShell window and run uv --version. Also note the exact path it installed to — if Claude later says “Server disconnected”, you paste that path into the install dialog and the problem goes away.

  2. 2

    Quit Claude completely, then reopen it

    Right-click Claude in the system tray (bottom-right, may be under the ^ arrow) → Quit. Closing the window leaves it running, and a still-running Claude will not see the PATH change from step 1.

  3. 3

    Download and double-click the bridge

    Use the button above; the file lands in Downloads. Double-click it and Claude opens an install dialog.

    Nothing happens? In Claude: Settings → Extensions → Advanced settings → Install extension… and pick the file from Downloads.

  4. 4

    Fill in the dialog, then restart Claude again

    Insightly API key — paste the key. Name this environment — a short label like demo1.

    Path to uv (macOS) — ignore this one entirely. Path to uv (Windows) — leave it as uv for now; it works whenever uv is on your PATH. Leave pod as na1 and the server URL as-is.

    Then quit from the system tray once more and reopen.

✓

Check it worked: in a new chat, ask “What's in this Insightly env?” — you should get real record counts, and “show the Insightly dashboard” should render an interactive panel. The first question can take up to a minute while uv fetches its own Python, once. After that it is fast.

Already running the classic version on macOS?

Nothing to undo. The two install side by side, share the same key store, and the classic one keeps working exactly as it does today.

  1. 1

    Install the bridge over the top — uv is already done

    Skip the Terminal step entirely. Download, double-click, and in the dialog reuse the same uv path your classic extension already uses: Settings → Extensions → Insightly SE MCP (internal) → Path to uv, copy that value across.

    For Name this environment, type the name of an environment you already have saved (say demo1) and paste that same environment's key. The bridge reads the very same ~/.insightly-mcp/keys.json, so it recognises the key, adopts the existing name, and all your saved environments appear in the picker immediately — no re-adding anything.

  2. 2

    Turn the classic extension off while you test

    Settings → Extensions → toggle Insightly SE MCP (internal) off. Both expose the same tool names, so with both enabled Claude may answer from either and results will look inconsistent.

    Same applies to the company-managed Insightly (Internal Release) connector if it is switched on — turn it off in the chat's tools menu (the ⚒ icon under the message box).

  3. 3

    ⌘Q, reopen, and confirm which one answered

    Ask “Run the Insightly connection_info tool.” The CF build reports served_from: cloudflare-worker and a version ending in -cf. The classic build reports neither.

    Switching back is just as easy: toggle the classic extension on and the bridge off. Your environments and keys are shared, so nothing is lost either way.
